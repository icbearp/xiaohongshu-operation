# XHS 选题灵感

本文件定义「选题研究」能力的标准流程，目标是从账号真实能力和用户真实任务出发，产出有证据、有可带走产物、能持续验证的选题。

开始前必须先读并执行：

- `xhs-source-audit.md`
- `xhs-value-conversion-gate.md`

标准链路：`账号能力与目标人群 -> 真实任务池 -> 来源审计 -> 价值评分 -> 合规检查 -> 3-5 个候选 -> 人工选择`。

## 0. 目标与原则

- 目标：产出值得发、能验证、能体现真实能力的选题，而不是泛泛的灵感词或通用工具清单。
- 默认输出：`3-5` 条选题，每条都要能直接进入内容生产。
- 原则：
  - 先看账号能力与真实任务，再用平台信号补充，不反过来追热点。
  - 互动潜力只能用于排序，不能替代真实价值。
  - 选题要和 `persona.md` 的语气、边界、风格保持一致。
  - 不做空泛大词，不做纯情绪口号，不做没有落点的热点搬运。

## 1. 输入

建议至少提供以下信息中的 2 项：

- 账号定位：做什么、给谁看、希望建立什么印象
- 目标内容：图文 / 长文 / 评论互动 / 轻剧情 / 复盘类
- 业务边界：可讲什么、不能讲什么、是否有合规限制
- 时间范围：今天 / 本周 / 最近 7 天 / 最近 30 天
- 参考对象：同类账号、竞品账号、话题词、URL、截图

如果用户只说“今天的小红书帖子”或信息不足，先从知识库判断目标人群、频繁真实任务、证据或演示产物、账号可交付能力。缺少关键证据时输出可验证方向和补证据计划，不立即生成通用工具清单。

## 2. 信号来源

选题优先混合以下四类信号。外部热度、收藏量和 GitHub Stars 只是发现线索，不是有效性证据。

### 2.0 真实任务与交付信号

- 账号实际做过的项目、服务、交付和复盘
- 岗位中高频、容易返工、需要判断或承担责任的任务
- 能展示的真实输入、过程、产物、结果和限制
- 账号确实能够持续讲述和承接的能力

### 2.1 平台侧信号

- 小红书同题材高互动帖子
- 评论区高频追问、争议点、反驳点
- 收藏高于点赞的实用型内容
- 近期重复出现的标题句式、封面信息层级、互动口令

### 2.2 需求侧信号

- 用户正在问什么、吵什么、纠结什么
- 真实场景里的阻塞点、反复踩坑点、决策分歧点
- 常见“想看但没人认真讲”的空白题目

### 2.3 账号侧信号

- 账号已有内容支柱
- 人设能讲的口吻和站位
- 适合持续连载的主题链路

## 3. 选题生成方法

### 3.1 先提主题框

先把输入压成一个主题框：

- 主题对象：人 / 事 / 产品 / 场景 / 问题
- 主题动作：分析 / 对比 / 复盘 / 教程 / 吐槽 / 观点
- 主题情绪：爽感 / 焦虑 / 争议 / 共鸣 / 反差
- 主题收益：省钱 / 省时间 / 少踩坑 / 变清楚 / 变好玩

### 3.2 再拆选题角度

每个主题至少拆出 `3` 种角度：

- 立场型：支持 / 反对 / 中立但有条件
- 过程型：怎么做 / 怎么避坑 / 怎么判断
- 结果型：做完会怎样 / 为什么别人做不到

### 3.3 生成标题骨架

优先用这些骨架起题：

- `为什么___`
- `我发现___`
- `___到底值不值`
- `别再___了`
- `___这件事，最容易被忽略的其实是___`

### 3.4 设计有用途的交流入口

只有在评论能补充真实场景、反例、限制或下一步案例时，才加入交流问题。不要为了评论量强行制造站队、争议或口令。

优先使用：

- 场景型：`你卡在流程的哪一步？`
- 条件型：`你的材料和这个案例有什么不同？`
- 反例型：`什么情况下这套方法不适用？`
- 验证型：`你更想看哪一种真实样本的完整处理？`

如果正文已经完整解决问题，也可以不设置互动问题。

## 4. 筛选标准

先按 `xhs-source-audit.md` 对外部材料建立来源台账，再按 `xhs-value-conversion-gate.md` 评分：

- 任务频率 `0-2`
- 损失强度 `0-2`
- 证据可得 `0-2`
- 判断含量 `0-2`
- 可带走产物 `0-2`
- 账号匹配 `0-2`
- 业务关联 `0-2`

只有总分至少 `9/14`、证据可得与账号匹配均不为 0、且不触发强制淘汰的选题才能进入生产。热度高但证据弱的方向排在有真实案例的方向之后。

## 5. 输出格式

默认一次输出 `3-5` 条，每条包含：

- 选题标题：`20` 字内优先
- 目标人群：谁最容易点进来
- 真实任务：对方实际要完成什么
- 失败成本：做错或不做会损失什么
- 证据：来源或演示产物
- 可带走产物：清单 / 表格 / 模板 / 判断标准 / 流程
- 业务关联：与账号可交付能力的关系
- 价值评分：`x/14`
- 内容结构：场景 -> 判断 -> 方法 -> 产物 -> 边界
- 风险提示：事实、合规、隐私和履约风险
- 下一步验证：发布前还要确认什么

建议附加一个“下一步可写方向”：

- 开头钩子
- 正文三段
- 评论区追问

## 6. 与 persona 的衔接

所有最终选题要过一次 `persona.md` 校验：

- 语气要像“小红书能说人话”，不要像报告
- 选题要短、直接、带一点情绪
- 如果账号是傲娇嘴硬风，标题和开头可以更有梗，但不能油
- 如果要做评论延展，先保留一句可接梗的收尾

简单说，选题不是只看“能不能火”，还要看“像不像这个账号会说的话”。

## 7. 失败与降级

如果平台信号太少、账号信息太弱，按下面顺序降级：

1. 先用账号定位生成 `3` 个基础主题框
2. 再用常见标题骨架补出候选题
3. 再用评论区提问把选题变具体
4. 如果仍然缺信号，直接输出“可验证问题清单”，让用户补充信息后再继续

禁止在信号不足时硬编“爆点”。

## 8. 推荐输出模板

```text

   目标人群：

   价值评分：
   内容结构：

2. 选题标题：
   ...
```

## 9. 使用建议

- 先做 `3-5` 条，不要一口气堆太多。
- 如果用户要后续写稿，保留“标题骨架 + 互动钩子 + 三段结构”这三件事。
- 如果后续要研究高互动样本，选题结果可以作为 `references/xhs-sample-research.md` 的前置输入，但必须独立创作。
