# 小红书内容实验与复盘

目标：让每篇内容只验证一个核心假设，使用账号真实可见数据复盘，不套用外部算法公式。

## 1. 发布前实验卡

每篇准备发布的内容必须记录：

```yaml
target_user: 目标人群
real_task: 真实任务
hypothesis: 这篇具体要验证什么
evidence: 支撑内容的来源与证明材料
single_variable: 本次唯一主要变量，如选题、封面信息层级或案例呈现
expected_action: 希望目标读者产生的可观察动作
risk_boundary: 合规、事实、隐私、能力或履约边界
baseline: 可比较的历史内容；没有则写无基线
```

不要一篇同时更换选题、标题、封面、正文结构、发布时间和互动方式后，再武断判断是哪一个因素有效。

## 2. 24 小时记录

记录平台实际可见字段，并注明哪些不可得：

- 曝光、点击或阅读数据：仅在后台实际提供时记录。
- 公开互动：点赞、收藏、评论、分享等页面可见数据。
- 评论内容：按下面的语义类别人工归类。
- 异常：审核、限流提示、删除、数据延迟或发布时间异常。

24 小时只做早期观察，不急于把波动解释成平台规律。

## 3. 72 小时记录

在同一口径下补录数据，比较：

- 是否仍有新增互动或搜索型长尾。
- 操作追问和场景咨询是否增加。
- 目标人群是否准确，还是吸引了无关流量。
- 内容承诺是否与实际评论反馈一致。

## 4. 评论分类

- `认同`：表达赞同但没有新信息。
- `补充`：提供经验、反例、工具或新条件。
- `反对`：质疑事实、方法、边界或结论。
- `操作追问`：询问步骤、参数、故障或怎么执行。
- `场景咨询`：描述自己的业务、岗位或材料，希望判断如何处理。
- `无关互动`：表情、泛夸、互关、广告或与主题无关。

对转化判断时，`场景咨询` 比泛点赞更接近服务需求，但仍不等于成交。

## 5. 漏斗诊断

按 `曝光 -> 点击 -> 阅读 -> 信任 -> 咨询 -> 履约` 检查。每层写四项：

- available_evidence：实际拥有的数据。
- observed_signal：观察到什么。
- confidence：高 / 中 / 低 / 不可判断。
- next_test：下一次只改什么。

没有后台曝光或点击数据时，不得从点赞数反推曝光量和点击率；没有咨询记录时，不得声称形成转化；没有真实交付时，不得把咨询包装为案例。

## 6. 复盘结论

只能选择：

- `继续`：证据支持继续验证同一方向。
- `修改`：问题明确，下一篇只调整一个主要变量。
- `补证据`：当前数据不足或事实支撑不够，暂停确定性结论。
- `停止`：连续实验没有价值信号、与账号不匹配或风险过高。
