# 小红书选题价值与转化闸门

目标：判断一个方向是否值得生产。不是“能不能写”，而是它是否对应真实任务、有证据、有可带走产物，并能自然体现账号真正可交付的能力。

## 1. 前置条件

先完成 `xhs-source-audit.md`。若来源审计结论为 `REJECT` 或 `UNVERIFIED`，不得进入可发布成稿；只能输出淘汰原因或补证据计划。

## 2. 价值评分

每项 `0-2` 分，总分 `14` 分：

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 任务频率 | 极少发生或人群不明 | 偶尔发生 | 目标人群高频发生 |
| 损失强度 | 不解决几乎无影响 | 有轻微时间或体验损失 | 明显影响时间、成本、风险或决策 |
| 证据可得 | 无真实材料 | 只有部分演示 | 有输入、过程、产物、结果或可复现实验 |
| 判断含量 | 一个按钮即可完成 | 需要少量选择 | 需要业务判断、取舍、校验或承担责任 |
| 可带走产物 | 只有观点 | 有步骤但不可复用 | 有清单、模板、表格、判断标准或完整流程 |
| 账号匹配 | 与定位和经验无关 | 可以偶尔讲 | 可持续讲且账号确实具备能力 |
| 商业相关 | 与服务无关或强行植入 | 弱相关 | 自然展示真实服务与交付物 |

通过条件：

- 总分至少 `9/14`。
- `证据可得` 与 `账号匹配` 均不得为 0。
- 不触发来源审计中的强制淘汰规则。

硬淘汰优先于总分。即使总分达到 9，也不能用虚假案例、收入承诺或违规导流补齐转化。

## 3. 必填输出

```yaml
target_user: 谁在看
real_task: 对方实际要完成什么
cost_of_failure: 做错或不做的损失
proof_asset: 可展示的真实材料或演示
human_judgment: 人需要判断什么
takeaway: 读者能带走的产物
account_fit: 为什么这个账号适合讲
service_relevance: 与可交付服务的真实关系
score: x/14
decision: PASS | REVISE | REJECT
```

- `PASS`：达到阈值，可进入内容生产。
- `REVISE`：有价值但缺证据、产物或账号匹配，先补齐。
- `REJECT`：低价值或触发硬淘汰，不生产。

## 4. 合规转化链路

默认顺序：

```text
真实问题 -> 判断过程 -> 可执行方法 -> 示例产物 -> 方法边界 -> 平台内具体场景交流
```

允许：

- 请读者在评论中描述自己的具体工作场景。
- 根据高频问题继续做公开案例、答疑或对照测试。
- 在平台规则允许范围内说明服务对象、交付物、周期和边界。

禁止：

- 暗号、谐音、联系方式变体、私域群和规避审核话术。
- “完整版私发”“这里不方便说”等人为制造的信息缺口。
- 用失业、暴富、错过机会等焦虑迫使用户咨询。
- 先承诺结果，再隐藏交付条件和风险。

## 5. 内容最低交付标准

通过后的选题必须有：

1. 一个具体工作场景，而不是宏大趋势。
2. 一个可观察的错误或成本。
3. 一段真实判断过程。
4. 一份能带走的产物。
5. 一个案例或可复现实验。
6. 明确的方法边界。
7. 与账号服务能力一致的平台内交流入口。

如果只能做到“推荐几个工具”，输出 `REVISE`，要求补真实任务和结果对照。
