# XHS 跨平台趋势研究

目标：在选题前了解一个话题最近 30 天在各平台被怎么讨论，找到真实需求和反复出现的问题，而不是只看小红书站内热度。

## 1. 何时使用

- 用户问“最近 ___ 有什么值得做的”“这个工具/话题现在火不火”
- 选题需要判断时效性，或想找站外已出现、站内还没被讲透的问题
- 高信号样本研究前，想确认一个说法在其他平台是否有反例

## 2. 研究工具（按可用性选择）

| 优先级 | 工具 | 说明 |
|---|---|---|
| 1 | `last30days` 技能（可选安装，MIT，`https://github.com/mvanhorn/last30days-skill`） | 汇总 Reddit、X、YouTube、TikTok、Hacker News、GitHub 与网页近 30 天讨论；配置 `XIAOHONGSHU_API_BASE` 后可加入小红书来源 |
| 2 | 当前 Agent 的网页搜索 | 用“话题 + 近 30 天 + 平台名”分别搜索，记录日期 |
| 3 | 浏览器模式下的小红书站内搜索 | 按 `xhs-runtime-rules.md` 的搜索约束执行 |
| 4 | 用户提供的材料 | 截图、链接、群聊讨论摘录 |

已安装 `last30days` 时按它自己的 SKILL.md 运行，不改写其引擎调用方式；未安装时不强求，直接用 2-4。

## 3. 输出：趋势卡

```text
话题：
时间窗口：YYYY-MM-DD 至 YYYY-MM-DD
各平台信号：平台 / 代表性讨论 / 互动量级 / 日期 / 链接
反复出现的问题：（按出现次数排序，至少 3 条）
分歧点：支持 / 反对 / 中性各一句
站内空白：小红书上还没被讲清楚的部分
证据等级：按 xhs-source-audit.md 标注
结论：值得做 / 补证据 / 不做（一句理由）
```

## 4. 衔接

- 趋势卡中的每条主张进入 `xhs-source-audit.md` 的来源台账；热度只算线索。
- “反复出现的问题”和“站内空白”作为 `xhs-topic-ideation.md` 的输入，再过 `xhs-value-conversion-gate.md`。
- 趋势卡写入 `knowledge-base/sources/`，文件名 `日期-trend-话题.md`。

## 5. 边界

- 不用海外平台热度直接推断小红书会火。
- 不复制其他平台的帖子原文和图片；引用只做短摘并注明来源。
- 涉及金融、医疗、法律的话题只做信息整理，不给个人化建议。
