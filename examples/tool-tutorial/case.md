# 例：工具/效率教程类账号

适用对象：分享开源工具、电脑软件、AI 工具和办公工作流的小红书账号。

## 目标

- 一篇只解决一个具体任务，让读者看完能照着做完
- 用官方来源和可复现步骤建立信任，不靠“神器”“必装”制造焦虑
- 从“推荐工具”转向“这个任务用它够不够”，让收藏与追问落在具体场景

## A. 选题信号

1. 从用户真实任务出发：传文件、批量改图、截图提字、整理相似照片、剪 Vlog 等
2. GitHub Stars、收藏数只作线索；必须回到官方 README、Release、系统要求核验
3. 记录：官方链接、版本号、核验日期、适用系统、已知限制（如未签名、早期版本）
4. 同一工具已经被大量泛推荐时，换成“某个人群 + 某个任务”的切口

## B. 内容结构

- 标题：先写任务或痛点，再写工具名（如“手机原图传电脑，不压缩也不登录”）
- 封面：展示使用后的状态或结果，短标题高对比；示意图要标“示意”
- 正文：场景 → 判断标准 → 步骤（3-6 步）→ 常见失败与排查 → 适用边界
- 结尾：围绕设备、系统或素材场景提问，引导平台内追问

## C. 证据与标注

- 已实机走通：写清设备、系统版本和测试日期
- 未实机测试：配图标为示意，正文写明“基于官方文档整理，未在 ___ 设备验证”
- 不作安全、速度、效果保证；涉及下载安装时提醒只从官方渠道获取

## D. 受众升级（可选）

基础操作教程容易被认为“问 AI 就能做”。积累一段时间后可升级为：

- 把工具放进一个完整工作流（输入 → 处理 → 交付物）
- 写给决策者的效率管理视角，同时写出执行者的真实工作现场
- 工具只作为加速器，人的判断、验收标准和返工成本才是正文重点

## 实操提示

- 一篇只讲一个工作流，排查部分比功能列表更有收藏价值
- 封面视觉风格确定后保持一致，新版本与旧版本对照后再替换
- 发布后关注“装不上/找不到设备/报错”类追问，作为下一篇选题来源
